# Backend Setup (FastAPI)

How to install, configure, migrate, seed and run the FastAPI backend.

Covers **Phase 0** (**T0.3**, **T0.5**), **Phases 2–4**, and the backend test tasks **T8.1–T8.2** in
[`todos.md`](./todos.md).
Related: [`supabase-setup.md`](./supabase-setup.md) (do this first), [`frontend-setup.md`](./frontend-setup.md).

> **Status.** The backend package is currently a scaffold: `backend/src/backend/__init__.py` is a
> placeholder and `backend/pyproject.toml` declares **no dependencies**. Steps marked
> **[not yet implemented]** will fail until the matching task in `todos.md` is done. They are included
> here so the guide is the complete target workflow.

## Prerequisites

* **uv** — install with `curl -LsSf https://astral.sh/uv/install.sh | sh`. This repo uses uv, not
  pip/venv directly (ADR-6).
* Python **3.14**, already pinned in `backend/.python-version`. uv downloads it automatically.
* A filled-in `backend/.env` — see [`supabase-setup.md`](./supabase-setup.md) Step 5.

## Step 1 — Install dependencies

```bash
cd backend
uv sync
```

`backend/pyproject.toml` is the single source of truth for dependencies (ADR-6). The root
`requirements.txt` was deliberately removed — do not `pip install -r` anything.

### Step 1a — Declare the dependencies **[not yet implemented — T0.3]**

`dependencies` is currently empty. Populate it:

```bash
uv add fastapi "uvicorn[standard]" sqlalchemy pydantic-settings \
       "psycopg[binary]" "pyjwt[crypto]" alembic
uv add --dev pytest pytest-cov httpx ruff
```

Notes on the non-obvious picks:

* **`pyjwt[crypto]`** — the `crypto` extra pulls in `cryptography`, which PyJWT needs to verify
  **`ES256`/`RS256`** tokens. Without it, JWKS verification fails.
* **`psycopg[binary]`** — psycopg v3 with prebuilt binaries. Chosen over `asyncpg` partly because this
  project uses synchronous SQLAlchemy (ADR-5).
* Avoid bare `python-jose`; PyJWT is what ADR-3 specifies.

### Step 1b — Prove the imports work — **RISK GATE (T0.3)**

Python 3.14 is very new, and wheels for `psycopg`, `cryptography` and `pydantic-core` may not exist yet.
Confirm before writing any feature code:

```bash
uv run python -c "import fastapi, sqlalchemy, psycopg, jwt, cryptography, alembic; print('ok')"
```

* Prints `ok` → continue.
* Tries to **build from source**, or errors → stop and lower the interpreter
  (`backend/.python-version`) to a version with published wheels, then re-run `uv sync`. Record the
  outcome in [`../architecture.md`](../architecture.md) §9.2.

`uv.lock` is generated by `uv sync` and **is committed** — reproducible installs are the point of ADR-6.

## Step 2 — Create `backend/.env`

Copy the committed template, then fill it in:

```bash
cd backend
cp .env.example .env
```

| Variable                | Where the value comes from                                                                  |
| :------------------------| :--------------------------------------------------------------------------------------------|
| `DATABASE_URL`          | [`supabase-setup.md`](./supabase-setup.md) Step 2 value 3. Must be `postgresql+psycopg://…` |
| `SUPABASE_URL`          | Step 2 value 1 — bare project URL, no trailing `/auth/v1`                                   |
| `SUPABASE_JWKS_URL`     | Optional; defaults to `<SUPABASE_URL>/auth/v1/.well-known/jwks.json`                        |
| `SUPABASE_JWT_AUDIENCE` | `authenticated` — use the `aud` observed in Step 3b                                         |
| `SUPABASE_JWT_SECRET`   | Leave **commented out** unless Step 3c found `alg: HS256`                                   |
| `CORS_ORIGINS`          | `http://localhost:5173` — must match the frontend origin exactly                            |

`.env` is gitignored (`.gitignore` lines 1–4). Verify:

```bash
git status --porcelain --untracked-files=all | grep -E '\.env$' || echo "OK: .env not tracked"
```

These variables are consumed by `Settings` in `backend/src/backend/core/config.py` **[not yet implemented
— T2.1]**, which is the only place that should read the environment.

## Step 3 — Run database migrations

Creates `courses`, `classes`, `registrations` with their constraints and indexes
([`../architecture.md`](../architecture.md) §3.4).

### Step 3a — One-time Alembic setup **[not yet implemented — T1.4]**

```bash
cd backend
uv run alembic init alembic
```

Then edit `backend/alembic/env.py` so it:

* imports `Base.metadata` from `backend.db.base`,
* reads `DATABASE_URL` from `Settings` rather than the hardcoded `alembic.ini` value.

Keeping one source of truth for the URL prevents "it works in the app but not in migrations".

### Step 3b — Apply the schema

```bash
cd backend
uv run alembic upgrade head
```

Always run Alembic **from `backend/`** — `alembic.ini` is resolved relative to the working directory.

Useful commands:

| Command | Purpose |
| :--- | :--- |
| `uv run alembic current` | Show the applied revision |
| `uv run alembic upgrade head` | Apply all pending migrations |
| `uv run alembic downgrade base` | Roll everything back — must work, per T1.5 |
| `uv run alembic check` | Detect drift between the models and the migrations |

`alembic check` is the fastest way to catch a model that was changed without a migration — a mismatch
means the ORM and the database disagree, which produces confusing runtime errors later.

## Step 4 — Seed sample data **[not yet implemented — T1.6]**

```bash
cd backend
uv run python scripts/seed.py
```

Creates at least 3 courses and 5 classes, including one with `capacity = 1` and one that is already full.
Both are needed by the end-to-end tasks T7.5 and T7.6. The script is idempotent, so re-running it is safe.

## Step 5 — Run the API

### Step 5a — Create the app module **[not yet implemented — T2.0]**

`backend/src/backend/main.py` does not exist yet. It must define `app = FastAPI(...)` plus the CORS
middleware and a `GET /health` route, so that the `backend:main` script entry in `pyproject.toml` resolves.

### Step 5b — Start the server

```bash
cd backend
uv run uvicorn backend.main:app --reload --port 8000
```

Verify it is alive:

```bash
curl -s http://localhost:8000/health
# {"status":"ok"}
```

Interactive API docs are at <http://localhost:8000/docs>.

### Step 5c — Verify the public endpoint

`GET /classes` needs no token, so it is the quickest end-to-end check that the app, the session and the
database are all wired correctly:

```bash
curl -s http://localhost:8000/classes | head -c 400
```

A `500` here usually means a database problem (bad `DATABASE_URL`, or migrations not applied). A `200`
with `[]` means everything works and the seed step has not run.

### Step 5d — Verify auth is actually enforced

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/registrations/me
# 401

curl -s -o /dev/null -w '%{http_code}\n' -X POST http://localhost:8000/registrations \
  -H 'Content-Type: application/json' -d '{"class_id": 1}'
# 401
```

To test with a real token, sign in on the frontend and copy the `access_token` from the session, then:

```bash
curl -s http://localhost:8000/registrations/me -H "Authorization: Bearer $ACCESS_TOKEN"
```

## Step 6 — Run the backend tests

```bash
cd backend
uv run pytest                                   # everything
uv run pytest tests/test_security.py -v         # JWT verification (T3.4)
uv run pytest tests/test_registration_service.py -v  # capacity/transaction rules (T8.1)
uv run ruff check .
```

The auth tests mint tokens with a locally generated key pair, so they need **no network and no Supabase
project**. If a test starts trying to reach `supabase.co`, a fixture is leaking a real client.

## Troubleshooting

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| `uv sync` tries to compile `psycopg` from source | No wheel for Python 3.14 | Lower `backend/.python-version`, re-sync — see Step 1b |
| `import jwt` works but `ES256` verification fails | Missing the `crypto` extra | Confirm `pyjwt[crypto]` is in `pyproject.toml` and `cryptography` imports |
| `NoSuchModuleError: Can't load plugin: sqlalchemy.dialects:postgresql` | `DATABASE_URL` missing the `+psycopg` driver | See [`supabase-setup.md`](./supabase-setup.md) Step 2 |
| `ModuleNotFoundError: No module named 'backend'` | Running `uvicorn` from the repo root instead of `backend/`, or without uv | `cd backend && uv run uvicorn backend.main:app --reload` |
| `Target database is not up to date` | Pending migrations | `uv run alembic upgrade head` |
| Every request with a valid-looking token returns `401` | `SUPABASE_URL` has a trailing `/auth/v1`, or `SUPABASE_JWT_AUDIENCE` is wrong | Fix `.env`; the `iss`/`aud` values must match Step 3b exactly |
| Browser reports a CORS error, `curl` works fine | `CORS_ORIGINS` does not match the frontend origin exactly, or `Authorization` is missing from `allow_headers` | Fix `.env`, restart the server, see [`frontend-setup.md`](./frontend-setup.md) |
| `409 class_full` when a seat should exist | `classes.registered` drifted from reality | Recompute: it must equal `count(*)` of the class's registrations |
